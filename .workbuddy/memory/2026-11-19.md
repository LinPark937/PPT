目标从“复现单篇 Nature 文献 PPT”升级为“客户上传任意论文 → 输出标准汇报 PPT”的产品：

2. 品牌模板库：学校/机构（如新东方、新航道）的模板 PPT（页脚底色、Logo、固定元素）入库，渲染时套用。

## 本次给出的技术判断（待用户确认后实施）
- 当前代码无 RAG/LLM/向量库；`paper_to_ppt.py` 只是 PyMuPDF 抽文本+图后按模板填空。
- 版权红线：商业交付不能随便抓网图或直接用出版社论文图。白名单建议：客户论文原图（客户授权）→ 用户补充上传 → Unsplash/Pexels/CC0/CC BY（带署名附录）→ 自绘示意图。Wikimedia CC BY-NC 不可商用，CC BY-SA 有传染性。
- 图片策略：不做全自动替换，做“候选图确认制”（ImageResolver 出 3–5 张候选 + provenance，用户确认后渲染）。
- 模板接入：python-pptx 应直接 `Presentation(template_path)`，清示例页时 drop_rel 保留母版/版式/主题/页脚/Logo；模板库存原始 pptx + 体检报告（母版、layout/placeholder idx、安全区、字体、品牌色）。当前 `Presentation()` 从零建的方式必须改。
- 架构关键前置：先把写死的 16 页重构为 DeckSpec(JSON) 驱动的页型渲染器（`spec.py` + `renderer.py`），图片和模板两个需求都挂在这层；旧 16 页迁成 spec 作为回归金标准。
- RAG 防幻觉：分块→召回→LLM 出 DeckSpec→校验器把所有数字/术语回溯原文，回不去就标红/丢弃。
- 数据起步：templates / assets(含 provenance+许可证) / jobs 三张表；论文默认本地处理，上传云端前需授权勾选。

## 待用户确认的三个前提
交付是否商用对外；品牌模板以 .pptx 母版还是素材包提供；本轮是否先做 DeckSpec 渲染器重构。
